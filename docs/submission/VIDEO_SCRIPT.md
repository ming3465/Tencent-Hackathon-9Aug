## 3. Input rules that make takes repeatable

These are not style notes. Each one is a known behaviour of the current build
and ignoring it will ruin a take.

1. **Interact with `E`. Never `Space`.** Phaser captures `SPACE` at the window
   level (`sandboxScene.ts:296`, capture defaults to true), so Space activates
   **no** DOM button anywhere in the game while the world is loaded.
2. **Activate dialog buttons with `Enter` — tap, never hold.** Key repeat fires
   the choice and then closes the dialog before the response text can be read.
3. **Close overlays with `Escape`.**
4. **Never hold `E` while a dialog is open.** A latched `JustDown` will
   re-open the dialog the frame after you close it.
5. **Pause ~1 second after every stop before the next input.** Camera follow is
   lerped at 0.09 and needs about a second to settle.
6. Player speed is **215 px/s**, normalised on diagonals. All hold times below
   are derived from it.
7. **Do not walk east along y ≈ 770.** The pond collider ends at y = 765 and the
   player's foot body is only ~6 px clear. The route below uses y ≈ 794.

```bash
ffmpeg -y -i /tmp/gameplay_raw.mp4 -i /tmp/voiceover.m4a \
  -vf "scale=1920:1080:flags=lanczos" \
  -c:v libx264 -preset slow -crf 19 -pix_fmt yuv420p \
  -c:a aac -b:a 192k -shortest -movflags +faststart \
  "Kampung SG-Game Demo Video-TheTwoGuys.mp4"
```

**Audio decision:** `screencapture -v` records video only, and this machine has
no system-audio loopback, so the gameplay track is silent. Default plan =
**narration only** (record in QuickTime → File → New Audio Recording). The game
*does* have synthesised audio, so shot 5's caption states it and the sound
toggle and volume sliders stay visible in the topbar throughout. Optional
upgrade if ≥ 15 minutes remain: capture app audio in OBS 32.1.2 instead.
